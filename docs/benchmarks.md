# 内存与性能实测

2026-11-07，Windows、Node.js v24.19.0，MoonBit 0.1.20260915 / moonc v0.10.13+cbb11c36f。
基线为提交 `6cfb8b8` 的 0.1.0，比较对象为 11 月 7 日的本地 0.2.0（尚未加入写入去重）。两个版本读取同一批合成文件。
每个命令启动一个独立进程，表中为单次观测，不是多次平均或性能承诺。

峰值内存是 Node `process.resourceUsage().maxRSS`，包含 Node 运行时、输入字节、解码结果及写入缓冲；
耗时从包装脚本加载 CLI 前开始，到进程退出前结束，包含文件 I/O，不含 Node 启动到包装脚本开始的时间。
原始结构化结果保存在 [benchmark-data.json](benchmark-data.json)。

## 相同输入的前后对比

| 输入 / 操作 | 0.1.0 峰值 MiB | 0.2.0 峰值 MiB | 0.1.0 秒 | 0.2.0 秒 |
|---|---:|---:|---:|---:|
| 8.03 MiB 长文本 / 转换 | 357.4 | 118.0 | 0.322 | 0.276 |
| 32.12 MiB 长文本 / 检查元数据 | 123.4 | 79.6 | 0.118 | 0.055 |
| 32.12 MiB 长文本 / 选一列、前 10 行 | 123.2 | 80.3 | 0.109 | 0.055 |
| 32.12 MiB 长文本 / 全部校验 | 131.6 | 96.7 | 0.118 | 0.199 |
| 32.12 MiB 长文本 / 转换 | 1739.0 | 268.0 | 1.691 | 0.844 |
| 200,000 行数值 / 选一列、前 10 行 | 80.2 | 51.6 | 0.060 | 0.028 |
| 200,000 行数值 / 全部校验 | 101.8 | 89.2 | 0.432 | 0.313 |
| 200,000 行数值 / 转换 | 548.4 | 322.7 | 1.128 | 1.091 |

32 MiB 长文本转换的峰值内存下降约 **84.6%**。改动包含：

- Writer 使用 MoonBit core 的连续字节缓冲区，替代逐字节动态数组；合并 section 时不再先生成中间 Bytes 副本。
- strL 索引仅保存位置、长度和类型；按选中的单元格解码，共享对象在本次批次中复用，Reader 不长期缓存全文。
- Node 文件输入直接使用读取到的字节缓冲，避免再复制一份输入。

长文本 `verify` 的耗时增加：完整校验先检查所有 strL 对象（包含未被引用的对象），
再按批次解码行；部分文字会解码两次，以避免长期缓存所有文本。检查/选列/转换的耗时和内存应分别看待。

## 扩大输入规模

0.2.0 在 **128.47 MiB 长文本文件**上的实测：

| 操作 | 峰值内存 MiB | 耗时秒 |
|---|---:|---:|
| 检查元数据 | 185.5 | 0.116 |
| 选取数值列前 10 行 | 185.2 | 0.109 |
| 校验全部行与对象 | 225.4 | 0.487 |
| 完整读写转换 | 829.8 | 3.919 |

长文本文件包含整数 id 和 strL；每个 strL 约 8 KiB，并带唯一前缀，避免生成器去重使测试规模失真。
数值文件为 200,000 行、8 个 double 列，文件大小 12.21 MiB。
宽表兼容性另由 `tests/wide.py` 验证 65,537 列，两者不是同一个容量场景。

这些结果说明本版能处理上述输入，不能外推为任意 128 MiB 文件或所有 512 MiB 文件的内存上限。
完整转换会保留所有行对象，数值多行数据的对象开销显著；大文件查看宜先选列/限制行数。
本版保留内存型 API，磁盘流式读写不进入 0.2.0。CLI 的 512 MiB 是输入拒绝阈值，不是已验证容量。

## 11 月 8 日：写入去重后的补充验证

相同 Windows / Node / MoonBit 环境下，加入 strL 写入去重后重新完成全部容量场景。
原始结果见 [benchmark-dedup-data.json](benchmark-dedup-data.json)。这次运行与宽表回归并行，
耗时受其他进程影响，不用于前后速度对比；下表只记录各独立转换进程的峰值内存。

| 完整转换输入 | 去重后峰值 MiB |
|---|---:|
| 8.03 MiB 长文本 | 118.0 |
| 32.12 MiB 长文本 | 269.2 |
| 128.47 MiB 长文本 | 856.4 |
| 200,000 行数值 | 323.4 |

这些长文本全部唯一，写入索引会产生额外开销，不能期待去重降低这类输入的内存。
重复内容的效果由 `tests/compat_interop.py` 独立验证：1,025 行、两列 strL 共用 3 个非空文本对象，
118/119 输出分别为 41,260 / 41,274 字节，与 pandas 输入文件等大；大小端均通过。
二进制样本的 3 次重复引用也只保存 1 个对象。该测试同时检查数值、标签和文本的外部读回结果。

## 复现

```sh
moon build --target js
python tests/benchmark.py --sizes 8 32 128 --output _build/benchmark.json
```

依赖与互操作测试共用 `tests/requirements.txt`。合成输入只保存在被忽略的 `tests/generated/benchmark/`。
比较旧版本时，在单独目录构建该版本，将 `--cli` 指向其 JS 入口；不要覆盖当前构建。
此基准独立于 CI 正确性断言，不以机器相关的时间或内存差异判定功能失败。
